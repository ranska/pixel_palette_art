# Pixel Palette Art - Guide pour Claude

## Vue d'ensemble

Extension ComfyUI (custom nodes) pour la manipulation de palettes de couleurs pixel art.
Auteur : Ranska | Version : 0.0.3 | Licence : open source

## Commandes essentielles

```bash
# Tests BDD (OBLIGATOIRE avant tout PR)
mamba spec/ --enable-coverage --format=documentation

# Tests rapides (pendant le dev)
mamba spec/ --format=documentation

# Tests d'un module spécifique
mamba spec/pixel_palette_spec.py --enable-coverage

# Installation des dépendances de dev
pip install -r requirements-dev.txt
```

## Principes fondamentaux

### Separation lib/ vs nodes/
- **lib/** = logique metier pure, 100% testable, aucune dépendance ComfyUI
- **nodes/** = adaptateurs fins vers ComfyUI, NON testés (wrappers d'intégration)
- Toute nouvelle logique va dans lib/, le node ne fait que l'appeler

### Pattern Registry (coeur du projet)
Trois registries indépendants, tous extensibles :
1. **ColorSpaceRegistry** - espaces colorimétriques (rgb, hsv, futur: hsl, lab...)
2. **ExporterRegistry** - formats d'export palette (gimp, hex, rgb)
3. **ParserRegistry** - formats de parsing palette (gimp, generic, adobe_aco)

Chaque composant s'auto-enregistre a l'import. Voir `docs/architecture-registries.md`.

### Auto-enregistrement
Les mixers, exporters et parsers se déclarent eux-memes via les `__init__.py` de leur module.
Ajouter un nouveau format = créer la classe + l'importer dans le `__init__.py` du module.

## Conventions de code

### Tests (Mamba/BDD)
- Framework : **mamba** (équivalent Python de RSpec)
- Assertions : **expects** (matchers fluides)
- Structure : `description` > `context` > `it` (comme RSpec)
- Convention de nommage des fichiers : `*_spec.py`
- Les specs mirrorent la structure de lib/ dans spec/
- Toujours lancer avec `--enable-coverage` avant un PR

### Style
- Commentaires et docstrings en francais
- Noms de classes/variables en anglais
- Dataclasses pour les modeles de données
- Context managers pour les operations temporaires
- ABC (Abstract Base Class) pour les interfaces

### Git Flow (IMPORTANT)
- Branche principale de travail : **develop**
- `master` = releases uniquement (tags), ne jamais PR directement vers master
- Workflow obligatoire pour chaque feature/fix :
  1. `git pull origin develop` (toujours partir de develop a jour)
  2. `git checkout -b feature/<nom>` (creer une branche feature)
  3. Travailler, commiter sur la branche feature
  4. `git push -u origin feature/<nom>`
  5. Creer la PR **vers develop** (jamais vers master)
  6. Apres merge, supprimer la branche feature
- Releases : quand develop est stable, merge develop → master et taguer
- **Lefthook** : pre-commit lance `mamba spec/` automatiquement
- **CI** : GitHub Actions sur push/PR (Python 3.10/3.11/3.12)
- Tests verts obligatoires avant PR
- Conventions PR : voir `docs/pr-conventions.md`

## Types ComfyUI custom

- `PIXEL_COLOR` : instance PixelColor (r, g, b, name, color_space)
- `PIXEL_PALETTE` : instance PixelPalette (colors[], metadata)

## Ajouter un nouvel espace de couleur

1. Créer `lib/color/color_spaces/<nom>/` avec `__init__.py`
2. Implémenter le mixer (methode `mix_with(color_a, color_b, ratio)`)
3. Optionnel : implémenter l'exporter
4. Auto-register dans le mixer : `ColorSpaceRegistry.register('<nom>', mixer_class=<Class>)`
5. Importer dans `lib/color/color_spaces/__init__.py`
6. Écrire les specs dans `spec/color/color_spaces/<nom>/`

## Ajouter un nouveau format d'export/parsing

1. Créer la classe héritant de `BaseExporter` ou `BaseParser`
2. L'enregistrer dans le `__init__.py` du module correspondant
3. Écrire les specs
